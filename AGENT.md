# Using the plugin

For developers (and AI agents) integrating `capacitor-rich-haptics` into a Capacitor app.

## TL;DR — first integration

1. Install:
   ```bash
   npm install capacitor-rich-haptics
   npx cap sync
   ```
2. Use:
   ```ts
   import { RichHaptics } from 'capacitor-rich-haptics';

   await RichHaptics.preset({ name: 'softTap' });             // common UX feedback
   await RichHaptics.play({ intensity: 0.8, sharpness: 0.4 }); // custom
   ```
3. Works on iOS (Core Haptics), Android (`VibrationEffect.Composition`), no-op-friendly on the web.

**Don't:** install `@capacitor/haptics` alongside this. They conflict, and the migration codemod handles the transition (`npx capacitor-rich-haptics migrate ./src --write`).

## Decision tree — pick the right API

| User wants… | Use this | Notes |
|---|---|---|
| Tap on a button click | `RichHaptics.preset({ name: 'softTap' \| 'sharpClick' })` | Cross-platform. Always start here. |
| UIKit-aligned impacts | `RichHaptics.preset({ name: 'mediumImpact' \| 'heavyImpact' \| 'softImpact' \| 'rigidImpact' })` | 1:1 with `UIImpactFeedbackGenerator` styles. |
| Confirmation / success | `RichHaptics.preset({ name: 'success' })` | Or softer: `confirm`. |
| Error / negative feedback | `RichHaptics.preset({ name: 'error' })` | Or softer: `reject`. |
| Picker / segment / detent | `RichHaptics.preset({ name: 'scrollTick' \| 'detent' \| 'selectionStrong' })` | From least to most prominent. |
| Long-press recognized | `RichHaptics.preset({ name: 'longPress' })` | |
| Drag begin / end | `RichHaptics.preset({ name: 'dragStart' \| 'dragEnd' })` | Pair with `useHapticDrag` for live params during the drag. |
| Toggle / switch flip | `RichHaptics.preset({ name: 'toggleOn' \| 'toggleOff' })` | |
| Accordion expand / collapse | `RichHaptics.preset({ name: 'expand' \| 'collapse' })` | |
| Keyboard typing | `RichHaptics.preset({ name: 'keyTap' })` | Use `preload` + `playPreloaded` if firing >10×/sec. |
| Subtle ambient cue | `RichHaptics.preset({ name: 'subtle' \| 'pop' })` | |
| Custom one-shot tap | `RichHaptics.play({ intensity, sharpness })` | iOS uses Core Haptics; Android maps to Composition primitives. |
| Mid-gesture continuous feedback | `useHapticDrag()` (React/Vue) or `startContinuous` + `updateParameters` + `stopPlayer` | Killer feature. |
| Themed pattern (heartbeat, level-up, …) | `RichHaptics.playPattern({ pattern: <name> })` | 60 built-ins; tree-shake by importing the named pattern directly. |
| Custom multi-event pattern | `ahap()` builder + `RichHaptics.playPattern` | Don't write AHAP JSON by hand. |
| Hot-path tap (typing, scrolling) | `preload` once, then `playPreloaded` repeatedly | Sub-ms latency. Pair with `engineDidReset` listener. |
| BPM-locked metronome | `startBPMLoop({ bpm, pattern })` | Returns `{ stop }`. |
| Compose explicit timeline | `sequence(preset(...), wait(200), pattern(...)).play()` | Cleaner than `setTimeout` chains. |
| AHAP file from Apple Visualizer | Place in iOS bundle, call `playAHAP({ name: 'Filename' })` | iOS only. Cross-platform → use `playPattern`. |
| Per-app intensity slider | `RichHaptics.setIntensityScale({ scale: 0.5 })` | Multiplies every haptic globally. |
| App-wide kill switch | `RichHaptics.setEnabled({ enabled: false })` | Wire to a settings toggle. |

## Common recipes (copy-paste ready)

### React — button with haptic on press

```tsx
import { HapticButton } from 'capacitor-rich-haptics/react';

<HapticButton preset="softTap" onClick={onClick}>Tap me</HapticButton>
```

Or using the hook:

```tsx
import { useHaptics } from 'capacitor-rich-haptics/react';

function CTA() {
  const haptics = useHaptics();
  return <button onPointerDown={() => haptics.preset('softTap')}>Tap me</button>;
}
```

### React — drag with intensity that scales with pull distance

```tsx
import { useHapticDrag } from 'capacitor-rich-haptics/react';

function DraggableCard() {
  const drag = useHapticDrag();
  return (
    <div
      onPointerDown={() => drag.begin()}
      onPointerMove={(e) => drag.update({
        intensity: Math.min(1, Math.abs(e.movementY) / 100),
      })}
      onPointerUp={() => drag.end()}
    />
  );
}
```

### React — preloaded haptic for typing (lower latency)

```tsx
import { useEffect } from 'react';
import { RichHaptics } from 'capacitor-rich-haptics';

useEffect(() => {
  RichHaptics.preload({ id: 'typeTick', intensity: 0.25, sharpness: 0.8 });
  const handle = RichHaptics.addListener('engineDidReset', () => {
    RichHaptics.preload({ id: 'typeTick', intensity: 0.25, sharpness: 0.8 });
  });
  return () => {
    handle.then((h) => h.remove());
    RichHaptics.unload({ id: 'typeTick' });
  };
}, []);

// In keydown handler:
RichHaptics.playPreloaded({ id: 'typeTick' });
```

### React — accessibility-aware via `useReducedMotion`

```tsx
import { useReducedMotion } from 'capacitor-rich-haptics/react';

const reduced = useReducedMotion();
// returns true if Reduce Motion is on, kill-switch is off, or no hardware
```

### Vue 3 — same patterns

```vue
<script setup lang="ts">
import { useHaptics, useHapticDrag, HapticButton } from 'capacitor-rich-haptics/vue';
const haptics = useHaptics();
const drag = useHapticDrag();
</script>

<template>
  <HapticButton preset="softTap">Tap</HapticButton>
</template>
```

### Vanilla JS — anywhere

```ts
import { RichHaptics } from 'capacitor-rich-haptics';

document.querySelector('#myButton')?.addEventListener('click', () => {
  RichHaptics.preset({ name: 'sharpClick' }).catch(() => {});
});
```

### Custom pattern via builder

```ts
import { RichHaptics, ahap } from 'capacitor-rich-haptics';

const myPattern = ahap()
  .tap({ intensity: 1.0, sharpness: 0.9 })
  .wait(0.2)
  .continuous({ duration: 0.5, intensity: 0.6, sharpness: 0.2 })
  .rampIntensity({ from: 0.6, to: 0.0, duration: 0.5 })
  .build();

await RichHaptics.playPattern({ pattern: myPattern });
```

### Reuse + transform built-in patterns

```ts
import { RichHaptics, errorBuzz, levelUp, scale, repeat, reverse } from 'capacitor-rich-haptics';

// Half-volume errorBuzz played 3× — note: tree-shaken named imports
const subtle = repeat(scale(errorBuzz, { intensity: 0.5 }), 3, { gap: 0.4 });
await RichHaptics.playPattern({ pattern: subtle });

// Backwards level-up = level-down
await RichHaptics.playPattern({ pattern: reverse(levelUp) });
```

### Compose timelines with `sequence`

```ts
import { sequence, preset, wait, pattern } from 'capacitor-rich-haptics/sequence';
import { coinFlip } from 'capacitor-rich-haptics';

const intro = sequence(
  preset('softTap'),
  wait(200),
  preset('success'),
  wait(500),
  pattern(coinFlip),
);

await intro.play().promise;        // wait for completion
intro.repeat(3).play();             // repeat
intro.then(preset('warning')).play();  // chain
```

### Respect Reduce Motion

```ts
const { userEnabled } = await RichHaptics.isSupported();
if (userEnabled) {
  await RichHaptics.preset({ name: 'success' });
}
```

For one-off subtle taps (`softTap`, `scrollTick`, `subtle`), it's fine to call without checking — the plugin no-ops when disabled.

## What NOT to do

These are the mistakes AI agents (and humans) tend to make. Avoid them.

### 1. Don't `await` haptics in synchronous-feeling UI handlers

```ts
// ❌ delays state update by ~1-3ms (Capacitor bridge)
async function handleTap() {
  await RichHaptics.preset({ name: 'softTap' });
  setOpen(true);
}

// ✓ fire and continue
function handleTap() {
  RichHaptics.preset({ name: 'softTap' }).catch(() => {});
  setOpen(true);
}
```

### 2. Don't use `play()` in tight loops

`play()` allocates a new player per call. For repeated taps (typing, scrolling, button mashing), use `preload` + `playPreloaded`.

### 3. Always pair `preload` with the engine reset listener

iOS Core Haptics resets after audio session interruption (phone calls, screen recording, Siri). Subscribe to `engineDidReset` and rebuild — otherwise haptics silently die after the first interruption.

### 4. Don't use `playAHAP({ name })` for cross-platform code

Bundle AHAP files only work on iOS. Android approximates with a soft tap. For cross-platform, use `playPattern` or `playAHAPFromString`.

### 5. Don't pass intensity > 1 or < 0

The plugin clamps for safety, but it's a code smell. Map your domain values to `[0, 1]` first.

### 6. Builder gotcha: ramps default to the most recent continuous's start time

```ts
ahap()
  .continuous({ duration: 0.5, intensity: 0.5, sharpness: 0.5 })
  // ↓ defaults to time=0, runs DURING the continuous (overlap)
  .rampIntensity({ from: 0.5, to: 0.0, duration: 0.5 })
  .build();
```

`tap` / `wait` / `audio` / `at` reset that hint. After any of those, ramps default to the cursor.

### 7. Don't subscribe to `engineDidReset` if you're not using `preload`

Without preloaded patterns, there's nothing to rebuild. Harmless but useless.

### 8. Don't ship `@capacitor/haptics` alongside this

They both register iOS haptic plugins. Use the migration codemod.

### 9. Honor accessibility

Reduce Motion users expect haptic silence. The plugin respects it (`isSupported().userEnabled`), but check before firing patterns that would feel jarring (long continuous, loud `errorBuzz`).

### 10. Debug silence with `getDiagnostics()`

```ts
const d = await RichHaptics.getDiagnostics();
console.log(d);
// → { engine: 'core-haptics', engineRunning: false, lastError: 'Engine init: ...', ... }
```

Common signals: `engine: 'none'` → no hardware. `engineRunning: false` → engine paused (auto-resumes). `lastError` non-null → check the message.

### 11. Don't forget to scale with `setIntensityScale` instead of doing it per-call

If your app has a "Haptic intensity" slider, set it globally once. Don't multiply intensity yourself in every play call — that bypasses the kill switch and loses semantic meaning.

```ts
// ❌ per-call scaling
RichHaptics.preset({ name: 'success' });
RichHaptics.play({ intensity: 0.8 * userIntensity, sharpness: 0.5 });

// ✓ set once, plugin handles the rest
await RichHaptics.setIntensityScale({ scale: userIntensity });
RichHaptics.preset({ name: 'success' });  // automatically scaled
```

## Debugging

| Problem | Cause | Fix |
|---|---|---|
| Haptic doesn't fire on real iPhone | iOS Reduce Motion, app-level kill switch, missing hardware support, or global System Haptics disabled outside public API visibility | Check `(await RichHaptics.isSupported()).userEnabled`, `await RichHaptics.isEnabled()`, and the iOS Settings app |
| Haptic doesn't fire after a phone call | Engine reset | Subscribe to `engineDidReset` and re-preload |
| Haptic feels weak on Android | Device doesn't support Composition primitives | Inspect `(await RichHaptics.isSupported()).engine` — should be `composition`, not `basic` |
| `playAHAP` rejects with "AHAP file not found" | AHAP file not added to iOS app target | Drag into Xcode with "Copy items if needed" + "Add to targets" checked |
| Web build console shows "Plugin RichHaptics not implemented" | Normal — web is a no-op fallback | Wrap calls in try/catch or check `Capacitor.isNativePlatform()` |
| Patterns suddenly silent after audio interruption | Preloaded players invalidated | Re-preload in `engineDidReset` handler |
| Engine state mystery | Various | `RichHaptics.getDiagnostics()` returns `{ engine, engineRunning, preloadedCount, activeContinuousPlayers, registeredAudioCount, lastError }` |

## Naming conventions in your app

When wrapping the plugin (often a good idea — isolates the dependency for tests), follow these names so other engineers / agents recognize the layer:

```ts
// lib/haptics.ts
import { RichHaptics } from 'capacitor-rich-haptics';

export const haptic = {
  tap:     () => RichHaptics.preset({ name: 'softTap' }).catch(() => {}),
  click:   () => RichHaptics.preset({ name: 'sharpClick' }).catch(() => {}),
  success: () => RichHaptics.preset({ name: 'success' }).catch(() => {}),
  error:   () => RichHaptics.preset({ name: 'error' }).catch(() => {}),
  // App-specific custom presets:
  doorbell: () => RichHaptics.playPattern({ pattern: doorbellPattern }).catch(() => {}),
};
```

## When the user asks for haptic features

1. **Prefer `preset`** — cross-platform-correct and short.
2. **Reach for a named pattern import** when the user names a feel ("coin flip", "heartbeat", "celebration").
3. **Reach for `ahap()` builder** for anything novel.
4. **Reach for `useHapticDrag` / `startContinuous`** for gestures with continuous feedback.
5. **Reach for `preload`** only on hot paths (>10 fires/second).
6. **Always** wrap with `.catch(() => {})` in fire-and-forget UI code.

# Extending the plugin

How to add new presets, patterns, and transforms. Three audiences:

- **App-level extension** — make custom haptics in YOUR app, no plugin fork
- **Plugin-level extension** — contribute a preset/pattern back to this repo
- **Tuning** — how to choose intensity / sharpness / duration values

## Adding a preset to your own app (no plugin fork)

Most apps don't need to fork the plugin. You have three paths:

### Path A: Wrap an existing preset with a semantic name

If your "doorbell" feel is close to `sharpClick`, just alias it:

```ts
// lib/haptics.ts
import { RichHaptics } from 'capacitor-rich-haptics';

export const haptic = {
  doorbell: () => RichHaptics.preset({ name: 'sharpClick' }).catch(() => {}),
};
```

Cheapest. Use this when you don't need different *feel*, just different *naming* in your codebase.

### Path B: Custom `play()` with intensity / sharpness / duration

For a single-event tap with a feel that doesn't match any preset:

```ts
// "doorbell" — heavy short ping
export const haptic = {
  doorbell: () => RichHaptics.play({ intensity: 1.0, sharpness: 0.95 }).catch(() => {}),
};
```

Use this when you want a unique single-event feel. See [Tuning the feel](#tuning-the-feel) below for picking values.

### Path C: Custom AHAP pattern with the `ahap()` builder

For anything multi-event (a "doorbell" with two distinct dings, or a dramatic "vault opening" with rumble + click):

```ts
// lib/haptics.ts
import { RichHaptics, ahap } from 'capacitor-rich-haptics';

const doorbellPattern = ahap()
  .tap({ intensity: 0.9, sharpness: 1.0 })           // first ding
  .wait(0.18)
  .tap({ intensity: 0.7, sharpness: 1.0 })           // second ding (softer)
  .build();

const vaultOpenPattern = ahap()
  .continuous({ duration: 0.4, intensity: 0.4, sharpness: 0.1 })  // rumble
  .rampIntensity({ from: 0.4, to: 0.9, duration: 0.4 })           // rising
  .tap({ intensity: 1.0, sharpness: 1.0, time: 0.42 })            // unlock click
  .build();

export const haptic = {
  doorbell: () => RichHaptics.playPattern({ pattern: doorbellPattern }).catch(() => {}),
  vaultOpen: () => RichHaptics.playPattern({ pattern: vaultOpenPattern }).catch(() => {}),
};
```

Use this when the experience needs >1 event, parameter ramps, or attack/decay shaping. See `src/patterns.ts` in this repo for 60 built-in examples to crib from.

### Decision matrix — which path?

| Your need | Path |
|---|---|
| Different *name* for the same feel | A (alias) |
| Different *feel*, but a single tap/buzz | B (`play()`) |
| Multi-event, ramped, or orchestrated | C (`ahap()` builder) |
| Want it shipped to other consumers | Contribute to the plugin → next section |

## Adding a preset to the plugin (contributors)

A preset is a **single-event haptic with a semantic cross-platform name**, mapped to native primitives where possible. Adding one is a 5-file change (skip any and you'll get a build error or a runtime no-op):

### Worked example: adding a `doorbell` preset

Goal: when user calls `RichHaptics.preset({ name: 'doorbell' })`, get a sharp double-ding feel.

#### File 1 — `src/definitions.ts`

Add the literal to the `HapticPreset` union, in the most logical category:

```ts
export type HapticPreset =
  // ... existing presets ...
  // Specific physical metaphors
  | 'subtle'
  | 'keyTap'
  | 'bump'
  | 'loadingPulse'
  | 'doorbell';   // ← NEW
```

#### File 2 — `src/web.ts`

Add web fallback (vibrate pattern + Web Audio cue). Both records require an entry per `HapticPreset`:

```ts
const PRESET_DURATIONS_MS: Record<HapticPreset, number | number[]> = {
  // ... existing entries ...
  doorbell: [12, 80, 12],    // ← short-pause-short
};

const PRESET_AUDIO: Record<HapticPreset, { freq: number; duration: number; gain: number }> = {
  // ... existing entries ...
  doorbell: { freq: 1500, duration: 0.012, gain: 0.06 },   // ← high-pitched ding
};
```

#### File 3 — `ios/Sources/RichHapticsPlugin/RichHapticsPlugin.swift`

Add a case to `presetParams`. Returns `(intensity, sharpness, duration)`. **Note:** iOS presets are single-event for now; for multi-event presets like `success`, the engine plays a single representative tap and you'd model the multi-ding with an AHAP pattern instead.

```swift
private static func presetParams(_ name: String) -> (Float, Float, Double) {
    switch name {
    // ... existing cases ...
    case "doorbell":         return (1.0, 0.95, 0.0)   // ← NEW
    default:                 return (0.7, 0.5, 0.0)
    }
}
```

If your preset really needs multi-event behavior on iOS, ship it as a built-in AHAP pattern instead (see [Adding a pattern](#adding-a-pattern-to-the-plugin)) — that's the right tool.

#### File 4 — `android/src/main/java/.../RichHapticsPlugin.java`

Add a case to `playPresetByName`. You have three options ranked by quality:

```java
case "doorbell":
    // Option 1: Use a predefined effect when it matches (cleanest)
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.Q
            && hasPredefined(VibrationEffect.EFFECT_DOUBLE_CLICK)) {
        vibrator.vibrate(VibrationEffect.createPredefined(VibrationEffect.EFFECT_DOUBLE_CLICK));
    }
    // Option 2: Use Composition primitives directly (richer feel on API 31+)
    else if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S
            && vibrator.areAllPrimitivesSupported(VibrationEffect.Composition.PRIMITIVE_CLICK)) {
        vibrator.vibrate(VibrationEffect.startComposition()
            .addPrimitive(VibrationEffect.Composition.PRIMITIVE_CLICK, 1.0f, 0)
            .addPrimitive(VibrationEffect.Composition.PRIMITIVE_CLICK, 0.7f, 80)
            .compose());
    }
    // Option 3: Waveform fallback (works on any API 26+)
    else {
        playPattern(new long[] {0, 12, 80, 12}, new int[] {0, 255, 0, 180});
    }
    break;
```

Use `playMapped(intensity, sharpness, duration)` for single-event presets that don't need primitive-level control — it routes through the same `buildEffect` used by `play()`.

#### File 5 — `README.md`

Add a row to the right preset reference table (under Cross-platform UX presets):

```markdown
| `doorbell`     | Sharp double-ding                  | 1.0 / 0.95 / 0    | `EFFECT_DOUBLE_CLICK`      |
```

#### Verify

```bash
npm run build           # tsc must pass — TS will fail loudly if you forgot any record entry
npm test                # 277 tests; new preset doesn't break the parametric pattern tests
node bin/cli.js list    # smoke-test
```

Then test on a **real device** (iPhone 11+ for iOS, any Pixel 6+ for Android Composition). The simulator/emulator can't actually play haptics — they no-op silently.

### When NOT to add a preset

- Your "preset" needs >1 event with ramps → use a **pattern** instead (`src/patterns.ts`)
- Your "preset" is just a renamed alias for an existing one → wrap it in your app's `lib/haptics.ts` (Path A above)
- You're not sure if it's broadly useful → start as an in-app `play()` call; promote to preset only after dogfooding

### Quality bar for new presets

- **Cross-platform reasonable** — the iOS feel and Android feel should be the same *concept*. If they're radically different (rich Core Haptics vs flat OneShot), reconsider.
- **Distinct from existing presets** — if your `gentle-tick` is 95% the same as `subtle`, just use `subtle`.
- **Tested on real device** — emulators can't haptic. Period.
- **Documented in README** — the table is the canonical reference; if it's not there, users won't find it.

## Adding a pattern to the plugin

A pattern is a **multi-event AHAP composition**. Single file change.

### Worked example: adding `vaultOpen`

Goal: a dramatic "safe being unlocked" feel — rising rumble that resolves to a satisfying click.

#### File: `src/patterns.ts`

Add near similar patterns (this would fit `effects` or `mechanical`). **Always** wrap with `tag(category, description)`:

```ts
export const vaultOpen: AHAPPattern = tag('mechanical', 'Rising rumble resolving to a satisfying lock click.')(
  ahap()
    .continuous({
      duration: 0.4, intensity: 0.4, sharpness: 0.1,
      androidPrimitive: 'slowRise',  // Android API 31+ uses PRIMITIVE_SLOW_RISE
    })
    .rampIntensity({ from: 0.4, to: 0.9, duration: 0.4 })
    .tap({
      intensity: 1.0, sharpness: 1.0, time: 0.42,
      androidPrimitive: 'click',
    }),
).build();
```

Then add it to the `patterns` const-object near related entries:

```ts
export const patterns = {
  // ... mechanical
  lockClick,
  keyJangle,
  watchTick,
  gearShift,
  dialPad,
  ratchet,
  vaultOpen,    // ← NEW
  // ... rest
} as const;
```

That's it. The parametric tests in `src/patterns.test.ts` automatically validate every pattern in the export object — no test changes needed.

#### `androidPrimitive` hints — when to set them

Android 12+ supports 8 `VibrationEffect.Composition` primitives. Without a hint, the plugin picks one based on `intensity`+`sharpness` heuristics (CLICK / TICK / THUD / LOW_TICK). For better fidelity, set the hint explicitly:

| Hint | Use case |
|---|---|
| `click` | Sharp resolving moment |
| `tick` | Repeated subtle tick (typewriter, scroll) |
| `lowTick` | Very subtle, ambient repetition |
| `thud` | Soft collision, heavy landing |
| `spin` | Vertigo, rotation, dial-spinning |
| `quickRise` | Rapid build-up (jump, button arming) |
| `slowRise` | Gradual build-up (modal opening, level-up start) |
| `quickFall` | Rapid drop (game over, dismissal) |

Hints are stripped by iOS automatically (Core Haptics is fine-grained enough not to need them).

### Quality bar for patterns

Patterns must be **authored, not random**. Each one should evoke a specific feeling. The trick is to pick a real-world physical metaphor and reverse-engineer the haptic envelope from it. See `src/patterns.ts` for 60 examples — `coinFlip`, `heartbeat`, `gameOver` etc. are all built around physical intuitions.

Test on a real iPhone before merging. AHAP feel is non-obvious from the JSON alone.

## Adding a transform

Pattern transforms (`combine`, `repeat`, `scale`, `stretch`, `reverse`, `delay`, `morph`) live in `src/transforms.ts`. They take an `AHAPPattern` (and possibly other args), and return a **new** `AHAPPattern`.

### Conventions

- **Don't mutate inputs.** Return a new pattern; the input pattern object should be reusable after the call.
- **Honor `Metadata`.** Carry it through (or merge sensibly if combining two patterns).
- **Use `getPatternDuration(p)`** if you need the total length — it walks the pattern correctly.
- **Re-export is automatic** via `export * from './transforms'` in `src/index.ts`.
- **Add tests** in `src/transforms.test.ts`. The pattern: fixture pattern → transform → assert structure of result.

### Worked example: adding `pingPong` (forward then reverse)

```ts
// src/transforms.ts
export function pingPong(pattern: AHAPPattern, gap = 0): AHAPPattern {
  return combine(pattern, reverse(pattern), gap);
}
```

```ts
// src/transforms.test.ts
it('pingPong appends reversed copy', () => {
  const p = ahap().tap({ intensity: 1.0 }).build();
  const pp = pingPong(p, 0.1);
  expect(pp.Pattern.length).toBe(2);
});
```

## Tuning the feel

How to pick `intensity`, `sharpness`, and `duration` values that match a physical sensation.

### Intensity (0.0–1.0)

| Range | Sensation |
|---|---|
| 0.0–0.15 | Imperceptible / barely-there. Use sparingly — most users won't feel it. |
| 0.15–0.35 | Subtle ambient cue (`subtle`, `scrollTick`). Good for repetitive feedback that shouldn't fatigue. |
| 0.35–0.6 | Noticeable but light (`softTap`, `keyTap`, `confirm`). Standard UI press. |
| 0.6–0.85 | Clear, deliberate (`mediumImpact`, `success`, `info`). Confirms a meaningful action. |
| 0.85–1.0 | Maximum (`heavyImpact`, `error`, `sharpClick`). Reserve for events that demand attention. |

### Sharpness (0.0–1.0)

This is **frequency content**, not loudness. iOS Core Haptics: low = ~50 Hz thump, high = ~300 Hz click.

| Range | Sensation |
|---|---|
| 0.0–0.2 | Deep thud. Bass-heavy. Feels physical, like dropping a heavy object. (`softImpact`, `bump`, `gentlePulse`) |
| 0.2–0.5 | Round/full. Balanced, body-sized. (`softTap`, defaults) |
| 0.5–0.8 | Clear click. Crisp without being needle-sharp. (`mediumImpact`, `success`) |
| 0.8–1.0 | Sharp. Tip-of-finger snap. Cuts through noise. (`sharpClick`, `selectionStrong`, `keyTap`) |

**Rule of thumb:** sharper = "smaller" event, softer = "bigger" event. A "boom" is low sharpness, a "tick" is high.

### Duration (seconds)

| Value | Behavior |
|---|---|
| `0` | **Transient** — instantaneous tap. Most presets. |
| `0.04`–`0.1` | Short continuous (a "snap" or "thud"). Use sparingly — feels heavier than transients. |
| `0.1`–`0.5` | Sustained continuous. Use with `rampIntensity` for fades. |
| `0.5`–`2.0` | Long ambient. Reserve for breathing, loading, or meditation patterns. |

### Real-world examples

| You're modeling… | i | s | d |
|---|---|---|---|
| Light button press | 0.5 | 0.7 | 0 |
| Plastic snap (Lego) | 0.7 | 1.0 | 0 |
| Heavy book closing | 0.9 | 0.1 | 0.05 |
| Pencil tap on paper | 0.3 | 0.95 | 0 |
| Distant thunder | 0.4 | 0.0 | 0.6 |
| Phone vibrate | 0.7 | 0.2 | 0.4 |
| Pop bubble | 0.6 | 0.95 | 0 |

When in doubt, **start in the middle** (i=0.6, s=0.5, d=0), test on device, then push values toward the metaphor.

# Contributing to the plugin

Internal architecture and dev workflow. Read this only if you're working **on** the plugin codebase.

## Stack

- **TS:** ESM-first, compiled with `tsc` to `dist/esm/`, bundled with rollup to `dist/plugin.{js,cjs.js}`. Strict mode on.
- **iOS:** Swift 5.9, deploys to iOS 14+. Plugin lives in `ios/Sources/RichHapticsPlugin/`.
- **Android:** Java 21, namespace `com.sergeyfaraday.plugins.richhaptics`, lives in `android/src/main/java/.../`.

## Plugin invariants (don't break these)

- **Web plugin always succeeds** — no throws, just no-ops where unsupported. Apps must be safe to call any method on web.
- **iOS Core Haptics not supported = silent no-op** in `play`/`preset`/`playPattern`. `startContinuous`/`preload` may throw on hard-unsupported.
- **All numeric params clamped** to valid ranges. Never trust caller input.
- **Engine reset clears preloaded players.** When `engineDidReset` fires, app code re-preloads. The native side does NOT auto-restore.
- **`isSupported()` is the only way to discover capability.** Don't add more capability flags as separate methods.
- **Kill switch and intensity scale are orthogonal.** `setEnabled({ enabled: false })` short-circuits all play calls; `setIntensityScale({ scale: 0.5 })` multiplies intensity. Don't conflate.
- **AHAP shape matches Apple's spec exactly.** Many users paste raw AHAP from Apple AHAP Visualizer. Don't add fields that aren't real AHAP — except prefixed with `_` (like `_androidPrimitive`), which we strip on iOS.

## iOS native conventions

- Engine lifecycle: pause on `willResignActive`, resume on `didBecomeActive`, restart on `resetHandler`.
- `playsHapticsOnly = false` so AHAP audio events work.
- `isAutoShutdownEnabled = true` so the engine cleans itself up.
- Use `[weak self]` in all engine handlers — they retain otherwise.
- Continuous players use `CHHapticAdvancedPatternPlayer` (supports `sendParameters`). Transients use plain `CHHapticPatternPlayer`.
- Strip `_androidPrimitive` keys from pattern dicts before passing to Core Haptics — `sanitizeForCoreHaptics()`.
- Apply `intensityScale` by walking the dict — `applyIntensityScale()`.

## Android native conventions

- Three-tier engine: `composition` (API 31+) > `basic` (API 26+) > raw `vibrate(ms)`.
- Always check `vibrator.hasVibrator()` before calling `vibrate(...)`.
- `ContinuousLoop` re-triggers Composition primitives at ~30Hz. Honest fallback for live params (don't pretend it's smooth).
- Predefined effects (`EFFECT_CLICK`, `EFFECT_DOUBLE_CLICK`, `EFFECT_HEAVY_CLICK`) used in presets where they map cleanly.
- `_androidPrimitive` event hint: `primitiveForHint()` resolves the JS string to the Android constant; falls back to `primitiveForSharpness()` heuristic if absent or unsupported on this device.

## Adding a new plugin method

Cross-cutting: every new method touches **6 files**. Skipping any breaks the build or the runtime.

1. **`src/definitions.ts`** — add method signature to `RichHapticsPlugin`. Add new option types.
2. **`src/web.ts`** — implement no-op or sensible fallback in `RichHapticsWeb`.
3. **`ios/Sources/RichHapticsPlugin/RichHapticsPlugin.swift`** — add `@objc func myMethod(_ call: CAPPluginCall)`. Add to `pluginMethods` array.
4. **`ios/Sources/RichHapticsPlugin/RichHapticsPlugin.m`** — add `CAP_PLUGIN_METHOD(myMethod, CAPPluginReturnPromise);` (only if you use the Objective-C bridge file path; modern `CAPBridgedPlugin` macro pattern doesn't need this).
5. **`android/src/main/java/.../RichHapticsPlugin.java`** — add `@PluginMethod public void myMethod(PluginCall call)`.
6. **`src/testing.ts`** — add to `createMockHaptics` so consumer tests still type-check.

If the method takes a non-trivial AHAP pattern, consider adding it to `bin/cli.js` too.

## Things to think twice about

- **New public top-level exports** pollute IDE autocomplete. Prefer subpath exports (`/transforms`, `/testing`, `/sequence`) for power-user features.
- **New peer dependencies** are forever maintenance. Vue and React are already optional. Don't add a third UI framework adapter without a strong reason — point contributors at `useHaptics` for inspiration.
- **Changing AHAP shape** breaks pasted Apple AHAP Visualizer files. Keep `AHAPPattern` matching Apple's spec exactly; namespace any extensions with `_` prefix and strip them before passing to iOS engine.
- **Native crashes** on iOS: Core Haptics throws if engine isn't running. Always `try ensureRunning(engine)` before play.
- **Bundle size for consumers** — keep `patterns.ts` tree-shakeable (each pattern is its own `export const`; `"sideEffects": false` in package.json). Don't introduce module-level side effects.
